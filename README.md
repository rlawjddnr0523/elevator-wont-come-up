# Elevator Scheduling

Java 콘솔 엘리베이터 스케줄링 시뮬레이션입니다. 엘리베이터 대수와 상관없이 호출을 효율적으로 배정하고,
상태를 콘솔로 시각화하며, 모드(STANDARD / FAST / ECO / AUTO)별 성능을 비교할 수 있습니다.

전체 기능은 [기능 목록(FEATURES.md)](FEATURES.md)에서 확인할 수 있습니다.

## 실행

JDK가 필요합니다 (Gradle은 Wrapper가 처리합니다).

```bash
./gradlew run                        # 기본: 10층, 엘리베이터 2대, 정원 8명
./gradlew run --args="20 4 10"       # 20층, 4대, 정원 10명
./gradlew test                       # 단위 테스트
```

인자는 `[층수] [엘리베이터 수] [정원]` 순서입니다.

## 화면 읽는 법

```
              EV1     EV2
           ┌───────┬───────┐
 4F ··     │ [▲ 3] │       │
 3F ▲· (3) │       │ ]■ 0[ │
 1F ··     │       │       │
           └───────┴───────┘
```

- `[▲ 3]` 문 닫힘 / `]▲ 3[` 문 열림. `▲▼■`는 진행 방향(■ = 정지), 숫자는 탑승 인원입니다.
- 층 왼쪽의 `▲▼`는 해당 방향 호출이 눌려 있다는 뜻이고, `(3)`은 대기 인원입니다.

## 명령어

| 입력 | 설명 |
|---|---|
| `<층> <up\|down> [인원] [목적지]` | 호출. 예) `3 up 3 8` = 3층에서 위로, 3명, 8층행. 인원 기본 1, 목적지 생략 시 진행 방향 안에서 랜덤 |
| (엔터) | 시간을 1틱 진행 |
| `run <N>` | N틱 진행 후 화면·통계 출력 (자동 생성이 켜져 있으면 호출도 함께 발생) |
| `auto <on\|off>` | 랜덤 호출 자동 생성 켜기/끄기 |
| `auto rate <0~1>` | 틱당 호출 발생 확률 (기본 0.3) |
| `mode <standard\|fast\|eco\|auto>` | 배차 모드 변경 |
| `stats` | 통계 출력 |
| `compare <N>` | 같은 호출 패턴(고정 시드)으로 N틱씩 4가지 모드를 돌려 비교 |
| `exit` | 종료 |

최상층의 `up`, 최하층의 `down`, 범위 밖의 층·목적지, 호출 방향과 어긋나는 목적지는 거부됩니다.

## 동작 규칙

- 시간은 **틱** 단위입니다. 틱마다 엘리베이터는 한 층 이동하고, 층에 서면 문이 1틱 열렸다가 다음 틱에 닫힌 뒤 이동합니다.
- 정차 시 목적지에 도착한 사람은 내리고, **진행 방향이 같은 대기자**가 정원까지 탑니다.
- 만원이면 외부 호출 층은 무정차로 통과하지만, 탑승자의 목적지에서는 정차합니다.
- 정원 때문에 못 탄 사람은 호출이 유지되어 다른 엘리베이터가 처리합니다.
- 목적지는 **SCAN 순서**(가는 방향으로 먼저 훑고, 반대편은 돌아오며)로 정렬됩니다.

## 모드

| 모드 | 배정 | 한가할 때 |
|---|---|---|
| `STANDARD` | 가장 가까운 가용 엘리베이터 | 제자리 대기 |
| `FAST` | **예상 도착 시간(ETA)**이 가장 짧은 엘리베이터 (이동 + 중간 정차당 문 여닫기 2틱) | 층 전체에 고르게 분산 대기 (10층 2대면 3층·8층). 상태는 `PARKING`으로 표시되고, 호출이 오면 즉시 취소 |
| `ECO` | 전체의 절반(최소 1대)만 가동 | 제자리 대기 |
| `AUTO` | 평소엔 FAST, 10틱 연속 한가하면 ECO, 대기가 3명 이상 쌓이면 다시 FAST | - |

### 성능 비교 (참고)

10층 2대, 시드 40개 × 1000틱 평균 대기(틱). 대기 중인 사람의 대기 시간도 포함한 값입니다.
`stats`와 `compare`는 도착한 사람만 집계하고 시드 하나만 쓰므로 수치가 이 표와 다를 수 있습니다.

| 호출 확률 | STANDARD | FAST | ECO |
|---|---|---|---|
| 0.1 (한산) | 3.6 | **2.9** | 9.4 |
| 0.3 (보통) | 7.4 | 7.4 | 23.2 |
| 0.6 (혼잡) | 15.5 | 15.0 | 152.7 |

- 20층 4대, 호출 확률 0.1에서는 평균 대기가 STANDARD 4.4 → FAST 2.7로 줄어듭니다 (같은 조건의 벤치마크).
- FAST는 한산할 때 가장 빠르지만 혼잡할 때는 STANDARD와 비슷합니다. 대기 위치로 미리 이동하느라 이동량이 약 30% 늘어납니다.
- ECO는 이동량이 절반 수준으로 줄지만 혼잡해지면 대기가 급격히 늘어납니다.
- 호출은 층이 균등한 랜덤이므로, 출근 시간대처럼 특정 층 쏠림이 있는 패턴에서는 결과가 달라질 수 있습니다.

## 구조

```
src/main/java
├── Main.java            콘솔 입력 루프, 명령 처리, compare
├── Building.java        층/엘리베이터 보유, 호출 배정, tick(이동·정차·탑승/하차), 모드 전환
├── Elevator.java        상태, SCAN 경로 정렬, ETA 계산
├── Floor.java           호출 버튼, 대기자 목록
├── Person.java          호출 층/목적지, 호출·탑승·도착 틱
├── Direction.java       UP / DOWN / NONE
├── DispatchPolicy.java  모드별 규칙 인터페이스 (canServe, cost, shouldStop, onIdle)
├── StandardPolicy / FastPolicy / EcoPolicy, Mode
├── PersonGenerator.java 랜덤 호출 생성 (시드 지정 가능)
├── Stats.java           평균·최대 대기, 평균 탑승 등 통계
└── Renderer.java        콘솔 시각화
src/test/java/BuildingTest.java   JUnit 테스트
```

모드는 `if (mode == ...)` 분기 대신 `DispatchPolicy` 전략 객체를 교체하는 방식입니다. 새 모드는 `StandardPolicy`를 상속해 필요한 메서드만 바꾸고 `Mode`에 등록하면 됩니다.
